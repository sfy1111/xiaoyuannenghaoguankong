# 校园能耗管理系统需求规格说明书（V1.0）

> 文档类型：产品需求规格说明书 / PRD  
> 编制日期：2026-10-21  
> 产品对象：高校校园能耗管理系统（兼容单校区学校，适配中小学时按实际建筑与业务裁剪）  
> 建设前提：**学校已有 IoT 平台负责设备接入和基础时序数据采集**，本系统通过接口读取设备、计量属性、实时值、历史值、状态和质量信息。  
> 需求边界：**校园专用业务产品，而非通用可配置能耗平台**；内置固定业务菜单、指标、统计计算、报表及驾驶舱，不建设通用图表拖拽设计器、自由公式规则引擎、行业模板市场。  
> 需求级别：P0（首期必需），P1（建议二期），P2（可选扩展）。  
> 性能、完整率、响应等数值若标注“建议验收值”，属于本产品项目建议，不冒充国家标准强制阈值。

## 1. 项目背景、建设目标及业务边界

### 1.1 项目背景

学校存在教学、科研、办公、生活、餐饮、体育及后勤保障等不同使用场景。校园建筑分布广、用途差异大、上下课及寒暑假规律明显；能源由多入口、多站房、多计量层级供应，实际用能对象和费用责任主体常常不一致。仅依赖物业抄表和总账单，难以回答“哪个校区、哪类建筑、哪栋楼、哪个时段、哪个责任部门用了多少能源，为什么异常，如何节约”等问题。

已有 IoT 平台实现设备接入，因此本项目不重新建设 Modbus、DL/T 645 等物理采集协议服务，而是在已有实时/历史数据基础上完成**学校能源业务映射、统一统计口径、校园场景分析、异常处置和后勤业务管理**。

### 1.2 建设目标

| 编号 | 建设目标 | 具体结果 |
|---|---|---|
| G01 | 能源看得清 | 校区、建筑、能源品种、分项系统的能耗量及运行状态可在线查询 |
| G02 | 统计算得准 | 有明确计量边界、时间周期、来源、质量标记与可追溯计算口径 |
| G03 | 用能比得公平 | 按建筑类型、面积、人数、开放时间、教学日历及特殊设备分组比较 |
| G04 | 异常找得到 | 空置/非教学时间用能、夜间漏水、突增、设备异常有告警及处理闭环 |
| G05 | 费用管得住 | 分能源、分校区、分楼宇、分责任部门测算和核对能源费用 |
| G06 | 节能有依据 | 为定额、预算、节能措施、项目成效、年度报表提供可信数据 |
| G07 | 日常用得起 | 学校后勤人员通过固定页面即可使用，减少复杂配置与维护门槛 |

### 1.3 适用场景和前提

- 适用：高校、多校区高校；教学楼、实验科研楼、图书馆、宿舍、食堂、体育馆、行政办公、公共空间、集中能源站等。
- 可裁剪：中小学、职业学校可隐藏学院/科研/复杂宿舍收费等不适用模块。
- 能源品种：电力、用水、天然气、供热、供冷、蒸汽、生活热水；光伏发电、储能与其他能源作为按项目启用的既有业务页面。
- 原则上只做**数据监测和管理建议**，不直接执行断电、断水、阀门控制。若项目另行建设控制功能，应单独落实审批授权、联锁保护和设备安全要求。
- 学生宿舍预付费收费、贸易结算、能源交易、碳交易均不是首期核心；对外结算须另有合规计量和业务系统，不把监测仪表的估算值直接作为结算凭据。

### 1.4 范围内与范围外

**范围内（P0）**：校园能源总览、建筑台账、能源计量点维护、IoT 数据关联、实时监测、分类分项用能、楼宇/区域分析、能效指标、教学日历、告警闭环、费用测算与账单核对、统计报表、计量设备运维、权限及审计。

**扩展（P1）**：学院责任分摊、宿舍用能、食堂专项、实验楼专项、集中供能与管网、节水水平衡、预算考核、节能项目评估、光伏自发自用分析。

**明确不做（首期）**：通用拖拽驾驶舱、自定义图表编辑平台、任意表达式公式编辑平台、自动为所有行业生成计算规则、设备协议采集平台、学生缴费充值支付平台、用电远程拉闸控制、复杂预测调度优化。

## 2. 组织角色与权限

| 角色 | 管理目标 | 查看范围 | 可执行操作 |
|---|---|---|---|
| 系统管理员 | 管理账户、系统稳定性与基础参数 | 授权全部校区 | 用户角色、接口参数、日志、备份、字典维护；原则上不直接修改业务实测值 |
| 学校领导/决策人员 | 了解全校总量、趋势、预算、节能效果 | 全校聚合数据 | 查看驾驶舱、统计报告、异常督办与节能成效 |
| 后勤能源主管 | 统筹全校用能和年度目标 | 全校/全部授权校区 | 查看全部业务、审核修正、考核、费用方案、告警规则与报告 |
| 能源管理员 | 能耗日常统计与排查 | 所辖校区/建筑 | 台账、点位核对、统计分析、异常处理、报表、规则维护 |
| 物业/设施运维人员 | 维护计量器具、处理现场问题 | 分派区域/设备 | 设备状态、报警接单、现场巡查、工单反馈及计量设备维护 |
| 学院/部门能源联络员 | 关注本单位用能和责任考核 | 本学院/部门关联对象 | 查询能耗、费用分摊、指标排名、提交异议、节能反馈 |
| 宿舍管理员 | 宿舍楼公共能耗与异常用能 | 负责宿舍楼 | 楼栋/楼层能耗、水电异常、宿舍核查单；默认不能浏览学生敏感明细 |
| 财务人员 | 核对能源费用和预算 | 能源账单及授权部门 | 价格方案、账单导入、费用对账、分摊核对、导出汇总 |
| 审计/督查人员 | 核查数据与处理轨迹 | 授权时间/业务范围 | 查询原始来源、人工修正、规则版本、告警处置及导出记录 |

**权限原则**：按角色 + 校区/建筑/部门数据范围授权；“能查看”与“能修改/审批”分离；人工补录、异常修正和费用更改需要留痕；学生个人/宿舍房间级明细最小必要授权。

## 3. 业务数据模型与统计关系

### 3.1 四套关系不能混用

| 模型 | 层级示例 | 用途 |
|---|---|---|
| 空间建筑结构 | 学校→校区→片区→建筑→楼层→房间 | 地图、区域监测、面积强度、建筑定位 |
| 能源计量结构 | 能源入口→总表→支路表→建筑表→分项设备表 | 计量汇总、上下游差额、避免重复计量 |
| 组织责任结构 | 学校→学院/后勤处/承包单位→责任区域 | 责任统计、费用分摊、管理绩效 |
| 能源业务结构 | 能源品种→建筑用途→分项系统→具体设备 | 分类分项分析、能效比较、节能诊断 |

**关键要求**：一栋楼可能有多个学院、一个支路可能覆盖两栋楼、一个供冷站可能供多个建筑。系统须保存对象间的关联和有效期，不允许依靠建筑树直接推算所有计量关系。无法分清的费用或能耗作为“待分摊/未归属”显示，不能无依据计入某学院。

### 3.2 建筑分类（学校默认业务字典）

| 建筑类型 | 典型用能特征 | 关键分析指标 |
|---|---|---|
| 教学楼 | 上课高峰、假期低负荷 | 课时用能、教学日/非教学日、面积电耗 |
| 实验科研楼 | 设备持续运行、通风与洁净负荷 | 科研专用与公共用能分开、夜间基础负荷 |
| 图书馆 | 工作日开放与考试周延长开放 | 开放时段能耗、面积能耗、夜间能耗 |
| 学生宿舍 | 住宿、热水、晚间负荷 | 楼栋电水热、实际入住人均、夜间异常 |
| 学生食堂 | 烹饪燃气、电、冷库和用水 | 餐均电/水/气，营业日与假期对比 |
| 行政办公楼 | 办公时间、周末低负荷 | 工作日/非工作日、面积用能 |
| 体育场馆 | 大空间空调、比赛活动及泳池 | 场馆开放时段、活动日、专用设备能耗 |
| 信息中心/数据机房 | 24小时 IT 基础负荷、空调 | IT用电、机房辅助用电、PUE（满足条件时） |
| 校医院/卫生站 | 医疗卫生服务、保障负荷 | 独立楼宇能耗、运营时段、专项设施 |
| 后勤服务及商业 | 商户、水电气及经营时段 | 责任费用、经营/公共分摊 |
| 公共设施 | 路灯、广场、泵房、绿化灌溉 | 公共区域能耗、时段及节水水平衡 |
| 能源站 | 集中制冷/供热/热水等 | 输入电/气、产热/冷、供能损耗、运行效率 |

注：学校可维护建筑实际用途，但不提供任意业务模型设计器；对混合用途建筑，需记录不同面积区划及专用能源归属，防止错误比较。

### 3.3 关键主数据实体及必备字段

| 对象 | 必备字段 |
|---|---|
| 学校/校区 | 学校编码、名称、校区编码、地址、统计时区、投用日期、启停用状态 |
| 建筑 | 建筑编码、名称、所属校区、建筑类别、地上/地下建筑面积、适用考核面积、层数、投用年份、是否混合功能、责任单位、供冷/供热方式、能源入口 |
| 楼层/房间（按需） | 所属建筑、楼层/房间编号、用途、面积、责任部门、启停用状态；学生个人信息不作为计量基础字段 |
| 组织部门 | 部门编码、名称、上下级、负责人、成本中心、责任生效起止日 |
| 计量器具 | 表计编码、设备名称、能源类型、计量用途、表号、安装位置、型号、精度等级、校验/检定信息、是否计费、状态、IoT设备ID |
| 计量点 | 点位编码、业务名称、所属建筑/区域、能源类型、计量方向（入口/出口/支路/外供）、量值类型（累计/瞬时/区间）、物理单位、IoT属性ID、倍率处理、时间有效期、质量策略 |
| 计量关联 | 上级点、下级点、包含关系、方向、分摊方式、互斥标识、有效期、来源说明 |
| 价格方案 | 能源品种、供应商、价格类型、币种、时段、税费、固定费用、适用建筑/表计、生效期 |
| 教学历 | 学年、学期、教学起止日、考试周、寒暑假、调休及特殊活动、建筑开放时间 |
| 考核指标 | 指标名、对象、统计期间、目标值、计算口径、来源标准、分母来源、生效期 |

### 3.4 时间及口径要求

- 基础粒度：按源能力保留原始时间戳，统计输出默认 15 分钟、小时、日、月、学期、学年、自然年（仅当数据满足粒度要求时）。
- 明确“自然日0:00—24:00”和学校特殊运行日边界的区别；默认按校园当地时区自然日。
- 学年、学期不替代自然年：财务、统计、节能考核使用各自明确周期；同一指标展示时需显示统计期间。
- 同比要有同口径可比基期；对寒暑假/学期错位场景，支持按“等效教学日/假期日数”对比，并标记方法。
- 学生人数、住宿人数、供餐数量、建筑面积属于随时间变化的**业务分母**，必须保存适用日期和来源，不得用当前人数覆盖历史指标。

## 4. 数据接入、计量标准化与数据治理

### 4.1 IoT 平台接口（P0）

IoT 平台必须能够向本系统提供：设备列表、设备所属网关和状态、属性点编码/名称/类型/单位、当前值/质量/时间戳、历史时间序列、设备在线状态和数据更新机制。建议支持增量订阅和历史查询；不强制指定具体协议格式。

**接口交互**：初次同步设备和属性点 → 能源管理员选择计量点关联物理 IoT 属性 → 预览最近7天数据 → 保存并验证 → 周期性获取数据 → 质量检测与统计 → 对异常下发计量核查任务。IoT 端不存在的点位或无有效历史值不得伪造数据。

### 4.2 IoT 点位映射（P0）

**页面**：左侧校区/建筑/表计树，中部计量点列表，右侧 IoT 点位选择及原始曲线预览。

**字段**：计量点编码、计量器具、能源品种、输入单位、业务单位、读数类型、IoT设备ID、IoT属性ID、采样期、倍率已处理标识、 CT/PT 关系（如适用）、源值方向、初始基线、启用时间、换表标志。

**操作**：逐点手动绑定、解绑、替换数据源、校验、查看曲线、绑定版本记录；允许导入表计台账，但不自动推断某建筑应绑定哪个实测点。可批量查看点位健康度，实际绑定仍须确认。

**校验**：
1. IoT 属性存在且有读取授权，量值为合法数值且存在时间戳。
2. 能源类型、单位量纲、累计/瞬时语义与绑定的计量点一致。
3. 电表 CT/PT 倍率只处理一次；上游已折算时下游倍率为1。
4. 同一计量点同一时间范围不允许两个未定义优先级的活动主源。
5. 累计电量与区间能耗不可混作一类值；换表回退不能直接当负用能。
6. 变更发布后保留原有效期和历史关联；影响范围提示到楼宇、指标及报表。

### 4.3 数据处理与校验（P0）

| 处理项 | 详细需求 |
|---|---|
| 累计量差分 | `区间用量 = 本期末有效累计读数 - 本期初有效累计读数`；读数跨期按统一边界对齐；出现回卷/换表/复位时依换表台账处理，不允许直接得到异常负值 |
| 瞬时功率或流量 | 仅在数据采样有效、积分规则明确且允许使用该数据时，通过时间积分得到区间量；不得把功率 kW 直接作为 kWh |
| 时间对齐 | 根据计量点采样频率聚合到统一窗，保留实际覆盖时长和有效样本率；频率不够时不能假定有15分钟真实值 |
| 无效值 | 空值、非数值、非法负增量、明显超限、时间倒退、重复数据、极长恒值等须标记；每项数据拥有质量状态 |
| 缺失处理 | 原则上展示缺失，不默认为0；如业务允许估算，须选批准方法、标识为估算并独立统计覆盖率 |
| 人工补录 | 提供表计读数、供气账单、水耗等离线补录，要求录入值、时间、单位、证据附件、原因、填报人与审核人 |
| 修正重算 | 修正源数据后触发关联日/月/学年指标重算；保存修正前后值、原因、版本和审批轨迹 |
| 质量看板 | 显示在线计量点数、有效点数、缺数点数、异常点数、连续异常时长、完整率、待审核修正数 |
| 数据溯源 | 任意楼宇能耗可以逐级追到计算口径、所涉计量点、原始 IoT 属性点和对应时间段样本 |

### 4.4 表计层级及防重复（P0）

- 支持总表/支表的明确父子关联，定义“包含、排除、外供、计量交叉、未覆盖”关系。
- 校园总用电优先使用明确可核验的购入/净购入边界，不能把学校总进线与其下属教学楼分表相加。
- 总表减子表仅用于**已验证覆盖关系且量纲、方向、时间一致**的场景，差值视业务口径标为“其他/未分项用能”或“计量差额”，不可未经确认直接解释为“线路损耗”。
- 单栋楼的总表与照明、空调、插座分表属于包含关系，不得在“楼宇总电耗”中重复相加；分项合计可与总表比较覆盖率。

### 5.2 不采用通用可配置设计的处理原则

- 页面、图表、统计指标的**类别在产品中预先设计并实现**，无需用户拖拽创建。
- 管理员可以维护建筑档案、日历、计量点关联、计量边界、统计排除项目、价格和报警阈值，属于正常的校园业务主数据维护，不视为独立通用配置平台。
- 标准计算规则由系统内置实现；如个别学校因“多个入口减外供支路”需要变体，只在**计量关系维护页由能源管理员人工逐点指定参与的表计及加减方向**，无任意表达式执行编辑器。
- 页面筛选维度固定：校区、建筑类别、建筑、能源、日期、责任部门、统计用途；根据登录权限显示候选数据。
- 各模块的统一统计结果须复用同一份经确认的业务指标数据，不允许驾驶舱、报表、费用页各自采用不同累计差分和父子表计算逻辑。

## 6. 页面级详细业务需求

本章为实施和界面原型设计的主要依据。每个页面的页面元素、字段、操作、校验和跳转关系均为产品必需行为。页面中的“来源状态”必须显示实际 IoT/业务数据状况，不能用固定示例数值替代真实数据。

### 6.1 综合驾驶舱

#### HOM-01 校园综合概览（P0）

**使用人**：校领导、后勤主管、能源管理员。  
**入口**：系统首页，默认展示用户授权范围内的学校全部校区。

**页面结构**：
1. 顶部统一筛选：校区（全部/单个）、日期（日/月/年）、当前统计区间、数据更新时间。
2. KPI卡：本期总用电 kWh、本期总用水 m³、本期天然气 m³、本期购入热量 GJ（按项目）、综合能源消费 tce（满足口径时）、能源费用元、已确认异常事件数。
3. 中部校园二维示意/建筑分布列表：按建筑着色或以排行呈现单位面积电耗/状态；不要求 GIS 精度或三维孪生。
4. 能源趋势：按能源品种分别展示曲线/柱图，不把不同单位未经折算堆叠。
5. 分类建筑能耗、重点异常建筑排行、同比环比、近期告警及待处理事项。
6. 数据质量提示：本期所用计量点的有效覆盖率及统计更新时间，缺失数据时对 KPI 标注“不完整”。

**交互**：点击任一建筑 → BLG-01；点击能源卡 → MON-01/02/03/04；点击异常 → ALM-02；点击费用 → CST-01；点击指标说明可见计算边界与口径；导出当前概览 PDF/图片（可隐藏敏感明细）。

**校验**：总量统计必须按统一计量边界排除父子表重复；缺失、估算和待确认数据必须区分；同比基期不可用时显示“无法比较”而不是 0%；本日未结束时提示“截至当前时刻”。

**输出**：全校概览查询条件传递给楼宇、统计和报表模块。

#### HOM-02 校区总览（P0）

**页面要素**：校区基本信息（面积、建筑数、教学/宿舍面积、统计学生数）、电水气热冷用量、能源费用、建筑分类结构、校区当日告警和数据完整性。

**操作**：切换校区、时段，查看各校区排名、向下钻取楼宇；可比较校区的绝对量和强度，但不得以总量直接评价校区管理水平。

**校验**：多校区公用能源站须明确分配边界；跨校区不相同的价格方案应单独计算再汇总。

#### HOM-03 能源专题大屏（P0）

**内容**：按能源类型展示电/水/天然气/热冷四类固定专题页面；每页含本期总量、变化、时间趋势、排名、异常和关键设备状态；外接大屏时支持全屏轮播、字号适配与刷新频率设置。

**交互**：能源类型切换不清空校区与日期筛选；单点/单建筑点击跳转业务详情。**不提供用户自行拖拉拽组件**。

### 6.2 电力、水、气、热冷监测

#### MON-01 电力运行监测（P0）

**筛选字段**：校区、建筑、区域/配电回路、计量层级、时间（最近24h/7d/自选）、计量点状态。

**展示字段**：当前有功功率 kW、累计电能 kWh、区间用电量 kWh、最大需量 kW（源支持时）、功率因数（有源时）、电压 V、电流 A（有源时）、在线状态、最后上报时间、数据质量。

**图表**：用电量时序柱图、功率曲线、日内负荷分布、峰平谷时段用电量、历史对比、建筑/回路分项用电量；电价时段统计依据实际有效价格日历。

**操作**：搜索电表、选择回路、调整时段、查看原始读数、切换总表/分表、导出时序；点击异常点打开原始采样和对应告警。

**校验**：累计量不作为瞬时消耗；峰值功率和最大需量不能混为同一指标；缺少电压/功率因数的表计隐藏对应图表并提示未接入。

#### MON-02 水资源监测（P0）

**内容**：全校/校区/建筑累计水表读数、区间用水、瞬时流量（如有）、日小时曲线、夜间最低流量、重点用水建筑与历史趋势、供水分区水平衡。

**业务字段**：供水入口、分区、生活/食堂/实验室/绿化/泳池用途、表计位置、是否回用水/再生水、是否排水计量。

**操作**：切换供水分区、按小时查看、异常波形标注、发起漏损核查；对用水量突增或非教学日连续流量发出可核查告警。

**校验**：水平衡需相同时间窗和覆盖的进/出水边界；无分区总表时只展示子表合计并提示覆盖范围，不宣传为全校供水总量。

#### MON-03 天然气监测（P0，如存在燃气）

**内容**：气量 m³、换算条件/标准体积状态（如源数据支持）、小时/日/月份用气、供气入口和重点食堂/锅炉、运行曲线、费用。

**交互**：按楼宇、食堂和锅炉房查看；显示计量单位与口径差异，避免实际体积与标准体积不经换算直接相加。

**校验**：瞬时流量与累计气量区分，气量异常不自动推断泄漏；天然气安全报警的正式处置须与具有资质的燃气安全系统及应急预案衔接。

#### MON-04 供热、供冷与生活热水监测（P0 按项目能源类型启用）

**展示**：建筑端供/回水温度、供回水流量、供热量/供冷量、瞬时热/冷功率、能源站产热/冷、管网分区耗量、能源费用（有数据时）。

**操作**：切换供暖季/制冷季、站点/建筑/系统、按日查看冷热量和供回温差；设备 COP/系统效率只有所需输入电量、产热/冷量及边界完整时计算。

**校验**：热量与冷量分别统计；能源站产出与建筑端使用量必须区分；不能将输入电力与其转换得到的内部冷热量直接相加计入同一综合能耗。

#### BLG-01 单栋建筑能耗详情（P0）

**顶部基本信息**：建筑编码、名称、类别、所属校区、建筑面积、适用考核面积、责任部门、主要能源形式、开放时间、计量覆盖率、数据更新时间。

**指标**：本期电/水/气/热冷实物量、同期值、单位面积电耗/用水（适用时）、能源费用、异常事件、当月预算执行情况（P1）。

**页面标签**：总览、分类分项、日内趋势、教学日历比较、计量点/表计、能源费用、异常记录。

**交互**：日期与能源种类联动；查看当前建筑的计量点贡献清单，显示“实测/分摊/估算/未覆盖”；点击父子表查看差额；导出楼宇分析报告。

**校验**：混合用途建筑的面积强度需要说明使用的面积分母；校区总量不受单栋楼不同计量精度导致的简单强行补齐影响。

#### EQP-01 重点用能设备监测（P1）

**对象**：大型空调机组、锅炉、冷站、热泵、循环泵、冷库、数据中心、通风柜集群、污水泵、路灯控制回路等。

**内容**：设备档案、耗能趋势、运行时长、开停状态（取 IoT）、能效、历史异常、维修关联。可与设备运维系统互链，不重复建设完整 EAM。

**校验**：运行状态缺失时不估算运行小时；设备 COP/PUE 必须满足边界和数据条件，否则展示“不可计算”。

### 6.3 能耗统计与分析

#### ANA-01 校园能耗总量与趋势（P0）

**统计条件**：学校/校区/建筑/建筑类别、能源品种、时间粒度（日/周/月/学期/学年/年）、日期范围、数据质量范围。

**内容**：能源实物量、各能源独立趋势、分建筑贡献、同比/环比、累计值、日均/教学日均、统计覆盖率；综合能耗只在适用折标口径齐全时展示 tce。

**交互**：柱线切换、时间下钻、点击某月获取日趋势，点击建筑进入 BLG-01；支持导出表格，导出中保留单位、统计周期和来源。

**校验**：单图不同能源类型不能直接堆叠物理量；折标系数变更保留版本和生效时间；同比要按等长有效统计窗口或显式标注不可比。

#### ANA-02 分类分项能耗分析（P0）

**建筑分类**：教学、科研、办公、宿舍、食堂、图书馆、体育、公共设施、能源站等。

**用电分项（默认）**：照明插座、空调、动力、特殊用电；可细化电梯、公共照明、信息机房、实验专用设备等，但细化仅在有对应实测支路或经过确认的分摊依据时展现。

**内容**：分类结构、分项占比、建筑类型趋势、分项统计覆盖率、同期对比、未分类余量、父子表差额。

**校验**：分类是建筑用途，分项是用电系统，两个维度不可直接相加；分项未覆盖不得按“其余均为照明”自动归集。

#### ANA-03 建筑排行与能效对比（P0）

**字段**：建筑名称、建筑类别、校区、建筑面积、统计期电量/水量、单位面积电耗、同比、数据有效覆盖率、排名、特殊设备标记、是否适用本次评价。

**交互**：默认同类型建筑比较；可以查看绝对量排行与单位面积排行；点击离群建筑进行环比和历史趋势诊断；支持选择排除高耗能专用设备（仅当单独计量并符合口径）。

**校验**：面积为0或缺失时不计算单位面积指标；开放时长、宿舍入住情况不可比时提示；样本不足不生成“优秀/较差”结论。

#### ANA-04 同比环比和用能结构（P0）

**内容**：日环比、周环比、月同比、学期同比、学年同比；用能强度增长率，按建筑类别和能源品种分解变化来源。

**操作**：查看基期、对比期的统计天数、有效样本覆盖率、节假日/寒暑假分布；图上可隐藏异常估算时段并重新计算对比结果。

**校验**：基数为0或基期缺失时显示“不适用”，不产生无限增长率；同比显示基期具体日期及可比说明。

#### ANA-05 教学日历与非教学时段分析（P0，学校特色关键页面）

**页面结构**：学年日历、学期/寒暑假/考试周分段、建筑开放时段、分类建筑非教学时段用能排行、趋势比较和异常列表。

**统计指标**：教学时段电量、非教学时段电量及占比、教学日均、假期日均、夜间基础负荷、假期异常用水次数。

**操作**：选择学期、校区、建筑、教学/非教学条件；按相似日历类型对比；点击异常进入告警详情；管理者可审批“特殊开放”解释并从不合理用能排行榜中排除，但不删除能源实耗。

**校验**：教师/学生课程表缺失时使用学校定义的日历和建筑开放时间，明确“以学校日历估计”；不得直接认为所有夜间负荷不合理（实验室/图书馆/机房例外）。

#### ANA-06 能源平衡与计量覆盖（P0）

**页面结构**：电力/供水/供热/供冷分能源计量流向简图、入口与支路合计、未覆盖部分、计量差额、覆盖率与排查记录。

**内容**： `入口量`、`外供量`、`已覆盖终端量`、`未覆盖/差额`。根据能源系统选择显示供能、生产、耗用、输配、外供，不强制一种公式适配所有系统。

**操作**：选择校区或站点、对比两个时间段、查看参与计算的点位及排除点位、发起补计量建议单。

**校验**：不完整或交叉计量时不得给出精确线损/漏损结论；可显示“计量平衡差额”而非“已确认损耗”。

### 6.4 校园场景专题

#### SPC-01 教学楼用能管理（P0）

**入口**：校园专项 → 教学楼。  
**筛选**：校区、教学楼、学期、教学日/非教学日、周次、小时范围。

**展示**：教学楼电水用量、照明/空调分项（若有）、课前课后能耗趋势、开课时段与非开课时段对比、教学楼面积电耗、假期低负荷及异常用能、建筑排行。

**交互**：鼠标悬停查看每小时能耗与是否教学时段；可查看“空课时持续高负荷”线索，点击生成巡查任务。

**校验**：无教室占用/课表数据时，结论只能依据楼宇开放时间，不能声称具体教室无人；教室是否空置属于外部课表/占用数据辅助证据。

#### SPC-02 实验科研楼用能管理（P1）

**内容**：建筑公共用能、科研专用设备用能、24小时设备基载、通风空调用能、实验室/学院归属、持续高耗能回路、特殊用能项目清单。

**字段**：科研设备类型、是否必须持续运行、特殊用能标记、设备管理责任人、实验室/学院、专项回路点位。

**业务规则**：正常的持续运行设备不得被“非教学时间高耗电”简单认定为违规；总量分析不随考核排除规则改变，评价计算可在符合标准和学校制度下单独列示专项扣除。

#### SPC-03 学生宿舍用能管理（P1）

**内容**：宿舍楼栋、楼层、公共照明与公共水电、集中热水、宿舍房间统计（有明确必要和权限时）、入住人数与能耗关系、夜间用电/用水变化、空置房间异常用电线索。

**字段**：宿舍楼、楼层、房间编码、实际入住人数（汇总或受限字段）、计量点、入住期间、公共/房间用能区分、费用责任类型。

**操作**：楼栋排行、楼层对比、实际入住人均用能、异常排查。建议默认显示楼栋聚合，不向普通后勤查看者提供房间/学生明细。

**边界**：不提供自动远程断电功能；不把能源监测值直接作为商业结算或学生预付费余额依据。

#### SPC-04 食堂能耗管理（P1）

**对象**：各食堂、承包档口/区域、厨房、冷库、排风、燃气与用水。

**指标**：电量、气量、用水、能源费用、餐均电/水/气、营业日均能耗、夜间冷库基础负荷、供餐量来源和完整率。

**交互**：营业日 vs 假期、食堂对比、能源结构、夜间负荷、餐均指标切换。供餐量由食堂运营系统接口或人工审核导入。

**校验**：餐均统计的供餐量为0或缺失则不出结果；承包商商用能源和学校公共能源必须区分。

#### SPC-05 图书馆和体育场馆专题（P1）

**图书馆**：营业/开放时间、考试周延长开放、空调和照明用电、面积电耗、开放日均电耗。  
**体育场馆**：场馆开放日、赛事活动、空调/照明/泳池/泵房专项用能、分活动日比较。

**校验**：有客流/入馆人次才计算人次能耗；“开放小时能耗”须用有效开放小时分母。

#### SPC-06 公共设施与校园照明（P1）

**对象**：公共路灯、景观照明、室外泵站、绿化灌溉、停车设施等。  
**内容**：时间开关计划（如来源可读）、回路用能、日落与夜间时段、路灯异常长亮线索、灌溉异常用水及公共设施能耗费用。

**边界**：展示建议，不直接自动操作照明或供水设备。

#### SPC-07 学院/部门责任用能（P1）

**内容**：学院、机关部门和承包单位的责任面积、归属计量点、直接实测用能、共享用能分摊、费用、预算及同比；支持负责人确认。

**操作**：能源管理员录入责任对应关系；分摊审核；学院查看本单位账单及明细，提出异议；管理部门复核后定期结算内部管理账。

**校验**：直接实测与按面积/人数/使用时长分摊的部分必须分栏；共享资源不允许多次全额归属；分摊比例同一有效期对同一池应合计100%，余量单列“未分配”；历史分摊依据可追溯。

#### SPC-08 集中能源站和管网（P1，如学校存在集中系统）

**对象**：锅炉房、换热站、冷水机组、热泵、集中热水站、蒸汽站及输配管网分区。

**展示**：站点输入电/气、设备耗电、产热/冷、外供或分配到建筑热/冷量、供回温、运行效率、管网平衡差额、站点日趋势与告警。

**指标**：设备或系统COP（条件满足时）、单位供热电耗、冷热量输出/输入、管网计量差额、供能利用率（口径可核对）。

**校验**：禁止把能源站产出热量与其输入电耗在同一个能源消费总量中重复计入；必须显示能源转换关系、源端与建筑端边界；冷热功率 kW 和冷热量 kWh/GJ 单位分开。

## 7. 能源费用、预算与账单

### 7.1 CST-01 能源费用总览（P0）

**页面内容**：本月电费、水费、天然气费、供热/供冷费、总费用、上月/去年同期、费用占比、校区和建筑费用排行；统计至最新可得时刻；费用属性区分“测算/账单/调整”。

**操作**：切换校区、日期、能源种类、供应商，钻取费用明细，导出对账单。

**校验**：若仅有单价而缺需量/基本费/税费等，则名称为“测算电费”或“可变电费”，不能冒充供应商最终账单金额。

### 7.2 CST-02 价格与账单规则管理（P0）

**价格字段**：价格方案编码、名称、能源类型、供应商、计费区域/电表、起止日期、计费单位、阶梯水价（如适用）、电价时段表及峰谷平单价、尖峰（如适用）、基本费、需量费/容量费、税费、服务费、减免项、版本说明。

**操作**：新增/修改价格有效期、查看重叠检查、复制上一期、试算某段能源费用、变更审批。

**校验**：同一对象相同计费时间不得有冲突价格版本；价格时段不得遗漏实际适用的日历/时间段；若电表不提供最大需量信息，禁止虚构需量费用；用水阶梯只能依据实际可用计费规则计算。

### 7.3 CST-03 能源费用明细与账单核对（P0）

**字段**：账单周期、能源品种、供方、账单编号、计费计量点、抄见量、供应商结算量、单价构成、可变费用、基本费用、税费、账单金额、系统测算、差额、差异说明、审核人。

**操作**：上传 PDF/Excel 账单附件、录入账单值、同周期测算对比、差异标记、审定与归档。

**校验**：对账差额应拆分为用量差、价格差、固定费/税费差、计量期错位差；原始账单附件不可被默默覆盖；审批前状态为“待确认”。

### 7.4 CST-04 校园费用分摊与部门成本（P1）

**内容**：学校公共能源、学院实测用能、共享建筑分摊、商业经营用能、后勤承担费用、能源费用责任表。

**分摊依据**：优先独立计量；不能独立计量时可按确认的面积/人数/开放时长/固定协议比例形成内部管理分摊；每一种方法应展示依据与生效日期。

**校验**：用于管理的分摊金额不等同于外部贸易结算金额；不得把同一笔成本在学校公共与学院费用中重复完整计入。

### 7.5 CST-05 能源预算与超支分析（P1）

**字段**：年度、预算责任对象、能源类型、预算金额、预算用量、月度/季度分配、预算调整记录、审批人。

**展示**：预算、实际已结算、系统测算、预计年度执行（建议值）、偏差、超支风险。

**校验**：预算调整保留原版本，预测值不得与实际已结算混列，学生规模或新增建筑变化需在评价说明中反映。

## 8. 异常监测、告警与处置闭环

### 8.1 ALM-01 告警中心（P0）

**列表字段**：事件编号、发生时间、校区、建筑、点位/能源类型、告警规则、严重级别、检测值与阈值、数据质量、当前状态、责任人、超时标记、关闭时间。

**筛选**：校区、建筑类别、能源、严重级别、告警状态、负责人、时间范围。

**操作**：确认、分派、暂挂、合并重复事件、查看趋势、转运维工单、填写处理结果、关闭或重开；支持通知站内消息或已有企业通信渠道（若接入）。

**状态**：新发生→待确认→处理中→待复核→已关闭；不成立可选择“误报”并说明原因；数据恢复与人工事件关闭为两个独立状态。

### 8.2 ALM-02 告警详情与追溯（P0）

**页面内容**：事件时间轴、发生对象、规则说明、阈值、原始/处理后曲线、同期相似时段对比、相关计量点、IoT 在线状态、关联设备/巡检工单、处理记录及附件。

**操作**：指定负责人、提交原因、上传照片、采取措施、复核结果、重开工单。每次变更记录操作人和时间。

### 8.3 ALM-03 预置告警规则（P0）

系统内置规则类型，只允许维护启用状态、作用对象、阈值/持续时长、通知人和特殊日排除规则；**不提供可视化条件编程器**。

| 告警类型 | 核心判断 | 校园业务约束 |
|---|---|---|
| 计量点离线/数据迟到 | 超过预期采样间隔尚无有效数据 | 先区分 IoT 故障与真正零用能 |
| 读数异常 | 累计表倒退、回卷、异常跳变、非法值 | 换表和维护期允许标记已知原因 |
| 用电突增 | 本期区间用量显著超过相似时段基线 | 需排除考试、科研活动等有据的特殊情况 |
| 非教学时间高能耗 | 建筑闭馆/寒暑假期间高于合理基线 | 实验室/机房/必要安全系统可设例外对象 |
| 水流连续异常 | 非使用期持续流量或用水显著上升 | 不等同认定漏水，需现场复核 |
| 夜间最小流量超限 | 连续多日夜间最小流量较高 | 必须有连续流量数据才启用 |
| 建筑能耗定额超限 | 统计周期指标超过学校批准限值 | 样本有效率不足则标记待判断 |
| 异常费用偏差 | 账单对账差额或预算超支 | 区分单价/用量/固定费用因素 |
| 计量平衡差额过大 | 上下游差额超过经审核阈值 | 前提为计量边界完整且同周期 |
| 设备运行异常 | 必要源数据存在且超过设定指标 | 设备安全处置以现有专业系统为准 |

**校验**：不允许同一规则在数据源缺失时大量生成“真实高能耗”误报；各级阈值需有默认建议但必须由学校能源主管审批生效。通知发送失败应重试并保留记录。

### 8.4 ALM-04 运维工单协同（P0，轻量闭环）

**字段**：工单编号、来源告警、任务类别、区域、设备、负责人、计划完成时限、处理动作、照片附件、实际完成时间、复核人、结论。

**操作**：告警转工单、人工新建、派单、接单、反馈、延期申请、结单复核；若学校已有运维工单系统，优先对接而不是强制再造一套完整工作流。

**验收重点**：告警转工单后可回到告警；工单关闭不自动抹去历史异常数据；高优先级告警可升级催办。

## 9. 统计报表与节能管理

### 9.1 RPT-01 报表中心（P0）

**报表清单**：校园能源日报、能源月报、校区月报、建筑分类用能月报、分项用能报表、能源费用月报、计量完整性报表、异常处置月报、学期能耗分析、学年/年度能耗分析。

**查询**：学校/校区/建筑类别/建筑、能源品种、统计周期、数据类型（实测/估算/修正）、导出格式。

**内容**：期初期末、用量、可比期、变动率、面积及生均指标（有效时）、单位、数据来源、口径、数据覆盖率、编制时间。

**操作**：查看固定报表、筛选、导出 Excel/PDF、权限范围共享、导出记录；按周期生成快照供审核归档。

**校验**：报表中注明统计时间、完整率、是否含人工补录、是否折标、是否扣除特殊设备；导出的合计应与同口径分析页一致。

### 9.2 RPT-02 重点学校/公共机构能源资源统计（P1，按实际报送要求）

**目的**：生成学校相关主管部门所要求的能源资源消费统计资料。不同主管部门和地区表式可能变化，因此仅在实施时按实际适用表格和数据项实现**固定报表模板**，不默认提供省级监管接口平台。

**操作**：填充能耗值、补充人员和面积统计、查看差错、审核导出、留存上报记录。

**校验**：与报送口径不一致的数据不得默认替代；须标记缺少的佐证资料和人工确认事项。

### 9.3 ENM-01 校园节能目标与定额（P1）

**对象**：校区、建筑类型、单栋建筑、学院/责任部门。

**指标类型**：年度电耗总量、用水总量、单位面积用电、生均能耗、生均水耗、单位面积综合能耗（适用时）、分项专项指标。

**字段**：目标周期、目标值、统计对象、适用标准或校内依据、排除规则、审核状态、责任人。

**页面内容**：目标完成率、达标数量及比例、超标排行、原因归因、整改责任、同比和专项对比。

**校验**：不是所有建筑都适用同一个单位面积限额；不同标准的面积、人数、实验设备扣除方法不可直接混用。

### 9.4 ENM-02 节能措施与项目管理（P1）

**对象**：空调时程优化、照明改造、节水器具、管网检漏、变频改造、光伏项目等。

**字段**：项目名称、建筑/设备、实施前基期、实施日期、措施描述、投资、责任人、计划节能量、实测观察期、费用、评估方法、依据资料、评价结果。

**操作**：建项目、上传前后对比数据、调整基线说明、记录实际投入、验收归档。

**校验**：仅“改造前后用电差”不能直接代表归因于措施的节能量；若未修正天气、使用人数、教学时长等关键变量，应明确标注“未经校正的变化量”。

### 9.5 ENM-03 节能公示和管理考核（P1）

**内容**：可公开的建筑用能排行、年度节能目标进度、典型节能案例及管理建议。支持校内展示屏/办公门户嵌入聚合结果。

**校验**：对外展示不包含学生房间和个人的敏感信息；未达到可比条件的楼宇不得发布带结论性评价的排名。

## 10. 基础档案与系统管理详细需求

### 10.1 BAS-01 学校、校区与建筑档案（P0）

**页面**：左侧学校/校区/片区/建筑树，右侧建筑列表、基本信息编辑、计量归属及数据覆盖摘要。

**输入字段**：项目编码、学校名称、校区名称、建筑编码、名称、建筑类型、建筑面积、考核面积、建筑用途、建成年份、供暖制冷方式、楼层数、责任部门、建筑启用/停用时间、经纬度/平面定位（可选）、楼宇照片（可选）。

**操作**：新增校区、创建建筑、编辑归属、维护面积历史、合并停用重复条目（须审批）、按建筑类型筛选、导入初始台账、导出建筑清单、查看关联计量点与告警。

**校验**：编码在学校内唯一；面积为非负且有计量单位；历史已经产生能耗的建筑不允许物理删除；建筑停用不删除历史数据；混合用途不能强制选单一责任部门进行费用归属。

**输出流向**：楼宇监测、面积强度分析、学院分摊、报告与告警区域信息。

### 10.2 BAS-02 组织、责任单位及共享区域档案（P0/P1）

**字段**：单位编码、名称、上级部门、部门性质（学院/管理部门/物业/商户）、责任人、联系电话、管理校区、责任建筑、责任面积、起止日期、成本中心。

**操作**：授权查看、关联建筑及楼层、维护共享面积、委托管理生效记录；责任变更需留历史，跨部门迁移仅改变后续责任。

**校验**：责任归属与费用分摊不是一回事；支持一个建筑多个责任部门，不允许因为重复关联使全校总能耗翻倍。

### 10.3 BAS-03 学年日历与开放时间管理（P0）

**页面**：月历视图、学期列表、特殊日详情、建筑开放时间维护。

**字段**：学年、学期名称/起止日、开学日、放假日、考试周、法定假期、调休工作日、暑假/寒假标记、教学日类型；建筑类别、每周开放表、特殊活动和开放例外。

**操作**：初始化年度日历、维护日期、上传学校校历、批量设置寒暑假、为图书馆/体育馆/科研楼配置独立时段、调整历史记录需审核。

**校验**：同一校区的主要学期不应无说明重叠；跨学年假期允许；时段覆盖午夜的定义要明确；学期变更引发相关分析缓存重算与版本标记。

**输出**：教学时段能耗分析、非教学时段报警、日历可比分析、假期专题。

### 10.4 BAS-04 计量器具台账（P0）

**字段**：器具编码、表号、名称、能源类型、安装建筑/位置、供能回路、计量用途、规格型号、准确度等级（如提供）、出厂编号、安装日期、检定/校准日期、下次检定/校准日期、资产状态、IoT设备ID、负责人、供应商、维保联系人。

**操作**：新增、更换、停用、资产转移、记录检定证书及有效期、关联计量点、查看历史读数、生成计量器具清册、检定临期提醒。

**校验**：表号/器具唯一；换表必须记录旧表终止示值、新表起始示值和切换时间；未纳入必检制度的仪表不误报为法定强检失效；依据具体法规及场景管理检定要求。

### 10.5 BAS-05 计量关系与点位维护（P0）

**页面**：分层计量树 + 计量点列表 + 右侧参与计算关系表。

**核心字段**：点位名称、编码、关联IoT属性、业务归属、能源类型、源数据语义、计量方向、用途（购进/消耗/产出/外供）、参与总量统计/子类分项统计、起止有效期、在父级关系中的“增加/扣减/仅用于展示”角色。

**维护逻辑**：
1. 用户先选择建筑/校区的统计边界，例如“教学楼A用电”。
2. 手动逐点从合法候选逻辑计量点中选择本建筑各电力进线、外供或需排除的回路；对每个点指定输入方向和计量角色。
3. 页面实时展示已经选中的点位清单、量值单位、最后上报时间、与其他总量的可能重叠提示。
4. 保存草稿→执行边界校验→管理员确认→生效；生效后按系统**内置“入口合计－明确外供/排除量”**等固定计算模型自动运算。
5. 如无明确总表，允许以已覆盖子表合计建立“已覆盖用电”，不可擅自命名为该楼“真实总用电”。
6. 修改点位后更新关系版本，提供受影响楼宇、指标、费用与报表明细，必要时选择重算范围。

**不提供**：任意输入 JavaScript/SQL/表达式、自助定义新的函数库、按照同名楼宇自动批量给公式绑定源点。

### 10.6 BAS-06 数据质量与人工补录（P0）

**页面**：缺数/异常记录、计量点时间序列、补录申请、审核记录、重算任务。

**补录字段**：能源类型、建筑/计量点、计量时间范围、期初读数、期末读数或区间量、单位、填报原因、凭据附件、是否真实仪表读数/账单值/估算值、审批人和补录时间。

**流程**：申请→数值/单位/时间窗校验→待审核→审核通过→生成修正版本→受影响指标重算→查询端标记“人工补录/修正”。

**禁止**：无审批覆盖原始IoT采样值；将估算值伪装成实测值；填报单个区间量时强制生成不存在的表计累计示值。

### 10.7 SYS-01 系统用户和权限（P0）

**字段**：账号、姓名/岗位、所属组织、角色、授权校区/建筑/部门、状态、最近登录时间、认证方式、有效期。

**操作**：创建/停用、权限授予与回收、密码及SSO策略、登录会话管理、操作审计查询。

**校验**：校区数据授权可下钻到建筑；读写权限分离；财务账单与宿舍房间级数据单独授权；删除用户不删除其历史审批记录。

### 10.8 SYS-02 接口任务与运行监控（P0）

**内容**：IoT同步状态、点位数、每项接口上次同步、历史补拉任务、接口错误、重试次数、待补数据时段；可按校区及设备筛选。

**操作**：管理员手动重试、查看错误、重新同步点位元数据、补拉指定历史范围、查看任务详情、配置接入凭据（按安全策略隔离展示）。

**校验**：接口任务重试幂等，不重复入库；中断恢复后不覆盖已审核修正版本；凭据不可明文出现在日志和界面。

### 10.9 SYS-03 审计与数据血缘查询（P0）

**内容**：点位绑定历史、表计更换、价格版本、日历变更、人工补录审批、能源边界调整、告警处置、报告导出记录。

**操作**：时间、操作人、业务对象过滤；审计事件详情支持变更前后字段对比；按照系统保留期限归档。

**要求**：审计记录不可由普通管理员随意删除；导出中保留操作记录与个人信息脱敏条件。

## 11. 主要统计指标与计算口径

> 以下为**校园业务指标定义建议**，不是原上传 NHJC 文件逐项规定的“校园官方公式”。每项计算都必须具有统计对象、实际点位集合、时间范围、分母来源和可用性条件，使用系统内置方法执行。计量关系由能源管理员手动维护，运行时自动计算。

### 11.1 基础能源指标

| 指标 | 计算方法/口径 | 单位 | 主要来源及限制 |
|---|---|---|---|
| 区间电量 | 有效累计读数期末－期初；按换表/回卷规则处理 | kWh | 需有有效相邻读数与倍率处理说明 |
| 平均功率 | 对有效瞬时功率按采样时间加权平均 | kW | 不能通过无完整窗口的随意算术平均代替 |
| 峰值功率 | 统计窗内有效瞬时功率最大值 | kW | 区别于供电商计费最大需量 |
| 电费峰时电量 | 在有效峰时日历内聚合各有效区间电量 | kWh | 时段价版本和分段时间精确一致 |
| 用水量 | 计量水表累计读数有效差分 | m³ | 换表与重复值须处理 |
| 瞬时用水流量 | 当前流量传感器读数 | m³/h | 不等同总用水量 |
| 天然气用量 | 按供气计量条件、有效计量数据累积 | m³或标准m³ | 不同体积状态不直接求和 |
| 供热/供冷量 | 合规热量表累计量差分或明确的能量积分模型 | kWhth/GJ | 显式显示热量/冷量及换算单位 |
| 设备用电量 | 其独立输入电表的有效区间量 | kWh | 无独立计量不得称为设备实测电量 |
| 计量点数据有效率 | 有效样本数/应采样本数（定义采样间隔） | % | 同时关注统计时间覆盖率 |

### 11.2 校园综合与强度指标

| 指标 | 计算方法 | 单位 | 业务规则 |
|---|---|---|---|
| 校园能源总消费（分能源） | 已确认校园统计边界的对应能源实耗汇总 | 各自实物单位 | 与发电/产热等内部转换产出分账，防止重复 |
| 综合能源消费量 | Σ（符合统计边界的能源消费实物量×有效折标系数），按照适用 GB/T 2589 口径 | tce | 系数依据、时期、边界、内部转换须可追溯 |
| 校园总用水量 | 已核验取水/购水边界的实际量 | m³ | 回用水、外供水、地下水等按学校采用的统计要求独立标明 |
| 建筑单位面积用电 | 建筑本期电量 ÷ 适用面积 | kWh/m² | 面积为0/缺失时不计算 |
| 单位面积综合能耗 | 建筑综合能耗 ÷ 适用面积 | kgce/m² | 与所依据的建筑能耗评价标准保持一致 |
| 生均用电量 | 符合口径的校园用电 ÷ 同期学生数 | kWh/生 | 学生数可为在校生、折算生数等，必须明确采用哪种 |
| 生均用水量 | 符合口径的校园用水 ÷ 同期学生数 | m³/生 | 学生人数和统计日期口径一致 |
| 宿舍入住人均用电 | 宿舍楼本期电量 ÷ 同期实际住宿人数 | kWh/人 | 统计周期长时建议按人数时间加权口径 |
| 餐均用水/气/电 | 食堂同期对应能源/资源量 ÷ 供餐数 | m³/餐、kWh/餐 | 供餐数为空、0或未经核实时不可用 |
| 建筑电耗同比增长率 | （本期电量－去年同期电量）÷ 去年同期电量×100% | % | 基期非零、可比周期且有效数据足够 |
| 能耗结构占比 | 同一折算体系或同一物理品种下某类÷可比总量×100% | % | 不同物理量不可直接同分母相除 |
| 建筑能耗目标完成率 | 实际周期指标与学校批准目标按规定方式比较 | % | 必须明确“越小越好”的指标和超额方向 |

### 11.3 校园时间与效率指标

| 指标 | 计算方法 | 单位 | 业务限制 |
|---|---|---|---|
| 非教学时段电量 | 区间电量在非教学时段之和 | kWh | 时间边界来自校历及建筑开放时间 |
| 非教学时段占比 | 非教学时段电量 ÷ 该建筑全时段电量×100% | % | 不代表全部可节省 |
| 教学日均电量 | 教学日总电量 ÷ 有效教学日数 | kWh/教学日 | 不把周末/寒暑假天数混入分母 |
| 假期日均用电 | 假期总电量 ÷ 有效假期天数 | kWh/日 | 特殊开放、科研连续运行需备注 |
| 夜间基础负荷 | 规定夜间窗口内有效功率的稳态代表值（例如统计期中位数） | kW | 表达为诊断指标而非实际节能量 |
| 夜间持续水流 | 夜间窗口的有效流量与持续时间 | m³/h、h | 只作漏损线索，需人工核查 |
| 设备 COP | 有效供冷/供热量 ÷ 同期输入电量（同能源计量单位换算后） | 无量纲 | 同期同设备边界，不能跨工况乱比 |
| 数据中心 PUE | 数据中心总能耗 ÷ IT设备能耗 | 无量纲 | 仅在边界、IT实测条件符合方法时使用 |
| 水平衡差额 | 入口供水－已核验出口/终端用途量（同周期） | m³ | 不能直接等同真实漏水量 |
| 站点供能差额 | 站端外供量－建筑端到达量（同时间、同量纲） | GJ/kWhth | 计量误差、时滞、未覆盖端必须标注 |
| 计量覆盖率 | 已被有效计量覆盖的用能对象或统计量÷明确统计对象/参考总量 | % | 定义必须选择“点位覆盖/面积覆盖/能源量覆盖”之一 |

### 11.4 能源成本指标

| 指标 | 计算方法 | 注意事项 |
|---|---|---|
| 可变电费 | Σ（各时段有效区间电量×适用时段电价） | 按有效电价、日历与时段计算 |
| 估算电费 | 可变电费 + 可计算的基本费/需量费/税费/其他项 | 缺项需提示“不含XX费用” |
| 用水费用 | 按实际价格方案对用水量计算 | 阶梯、污水处理费和固定费用视合同而定 |
| 天然气费用 | 对账单量×实际合同价等适用分项 | 未区分标况时需在对账界面提示 |
| 单位面积能源费 | 同期建筑能源费用÷面积 | 需要一致的成本覆盖范围 |
| 学院归属能源费 | 独立实测成本＋已审批共享分摊成本 | 分摊依据、责任期和金额可追溯 |
| 账单差额 | 实际账单金额－同周期系统估算金额 | 差额按数量、单价、税费、基本费等分类排查 |

### 11.5 双重统计边界示例

某教学楼有总电表 `M0` 和照明分表 `M1`、空调分表 `M2`、动力分表 `M3`，且三个分表均为 `M0` 所含支路：

- 教学楼总用电：`E楼宇 = ΔM0`（若 M0 还含对外转供等，必须由人工维护对应加/减点位，校验后应用固定总量模型）。
- 楼宇已测分项：`E分项覆盖 = ΔM1 + ΔM2 + ΔM3`。
- 尚未分项覆盖：`E未覆盖 = E楼宇 - E分项覆盖`，数值为负时显示“计量关系异常”，不把负值改为0蒙混过关。
- 不得错误计算 `E楼宇 = ΔM0 + ΔM1 + ΔM2 + ΔM3`。

另一学校如果没有 M0，只有支路表，则显示“已覆盖分项电量”，不自动声称“该楼总电量”。同一统计口径需要标明数据覆盖及计量边界。

### 11.6 内部转换能源防重复原则

例如热泵用电 `100 kWh`，输出热量 `300 kWhth`：电力输入是从校园外部购入的能源消费，热泵输出热量是校园内部转换后产出的有用能源。若在同一校园综合能耗边界里把 `100 + 300` 直接视为能源输入总量，会重复计入转换得到的能源。平台应以**能源消费、能源转换产出、建筑有用能消耗**三本独立统计账表示，综合能耗按选定现行标准及核算边界计算，不直接把内部二次转化结果重新加入输入总能耗。

同理：光伏发电量、自发自用量、上网量、电网购电量必须分开记录；可再生能源环境属性与碳核算另按适用标准，不把全部光伏发电量直接说成核证减排量。

## 12. 典型业务流程与页面流转

### 12.1 新校区/新建筑上线流程

1. 后勤管理员在 BAS-01 建立校区及建筑档案（面积、类别、责任部门、供能方式）。
2. 在 BAS-04 登记现场能源计量器具，核对计量位置与表计信息。
3. IoT 平台完成设备接入，SYS-02 同步设备/属性；BAS-05 中人工为计量点选择对应 IoT 属性并确认累计/瞬时语义。
4. 能源管理员逐个维护该楼入口、外供、分项、排除关系；执行与总表/账单的历史核对。
5. 数据质量通过后，楼宇在 HOM-01、MON、BLG-01、ANA 中上线显示；系统默认已有内置校园统计公式与页面，不要求用户创建图表或编写公式。
6. 校区/建筑用能正式纳入统计日期、口径版本与数据覆盖率向用户可见。

### 12.2 假期高用电发现和整改流程

ANA-05 按假期/教学日历发现某教学楼单位日负荷偏高 → ALM-01 产生经阈值判断的线索告警 → 能源管理员在 ALM-02 查看时段曲线、供电回路和是否存在特殊开放记录 → 转物业工单 ALM-04 → 现场检查空调/照明/科研特殊负载 → 录入原因与措施 → 复核后一段时间用能并关闭。历史能耗与原始告警轨迹始终保留。

### 12.3 夜间持续用水处置流程

MON-02 查看某宿舍片区连续夜间最小流量升高 → 告警中心生成“疑似异常用水” → 对比当期入住、维修和特殊活动 → 派发物业检查 → 发现管网漏损或其他原因并登记 → 修复后观察流量恢复 → 关闭事件。不能在仅有水表日读数、没有夜间流量采样情况下作“夜间持续流量”判断。

### 12.4 能源费用月结与审计流程

按自然月锁定统计期间 → CST-01 形成实测/估算用量及能源费用 → 财务导入供应商账单 → CST-03 自动比对量价费差异 → 能源管理员核查不匹配表计与账单期 → 如有必要 BAS-06 发起修正 → 审核后重算 → 财务确认本月结算结果 → 报表归档。严禁直接把经人工估算的监测费用当作银行付款凭据。

### 12.5 学院能源成本分摊流程（P1）

BAS-02 维护学院及责任面积 → BAS-05 核对其独立计量点 → CST-04 明确共享区域管理分摊基数与比例 → 月结生成实测与分摊两栏 → 部门负责人查看并提出异议 → 后勤复核/调整版本 → 财务汇总归档。共享成本多部门分配比例必须校验；不以“所有学院用电量简单加和”生成学校总电量。

## 13. 界面和交互设计规范

### 13.1 全局界面结构

- 桌面端后台为主；首页采用学校总览，左侧固定菜单、顶部当前校区/登录身份/告警入口、主体为图表和表格。
- 所有统计页面有统一的“校区 / 建筑或分类 / 能源类型 / 时间范围”筛选交互；避免相同含义在不同菜单里采用不同名字。
- 数值右侧明确单位，金额为元，电量 kWh，电功率 kW，热量 kWhth/GJ，水量 m³；保留区间起止、数据更新时间和来源质量说明。
- 图表默认适合学校运维人员：柱图用于区间用量，线图用于功率/流量趋势，同类量可堆叠；比例结构图仅在分母一致时使用。
- 宿舍房间、学院费用、财务账单只在授权范围出现，不通过隐藏菜单替代服务端的数据权限。

### 13.2 列表、详情与异常交互

| 场景 | 交互要求 |
|---|---|
| 空数据 | 说明“未接入/无数据/无权限/当前筛选无匹配”中的真实原因，禁止填充默认虚假数值 |
| 计算缺数 | 单项指标提示“数据不完整”并可查看计量点有效覆盖率 |
| 导出 | 导出与屏幕相同统计口径，包含筛选条件、单位、生成时间和统计说明 |
| 时间切换 | 指标卡、图表、排行、明细同步变更，不能部分仍使用旧时间范围 |
| 数据下钻 | 学校→校区→建筑→系统分项/计量点→原始时序，面包屑可返回 |
| 口径详情 | 点击指标名“i”显示统计公式、边界、排除项、标准或学校依据、更新时间 |
| 告警反馈 | 明确状态，提示处理时限和责任人，支持附件、审核、追溯 |
| 危险操作 | 点位换绑、数据修正、价格改动、结算锁定、权限变更需二次确认 |

### 13.3 固定页面视觉组件

推荐：首页 KPI 卡、能源趋势折柱图、建筑分类占比、异常排行榜、二维校区平面图或建筑分布示意、同类建筑横向对比条形图、计量拓扑树、告警表格、费用结构图、日历热力图。

**不开发通用组件市场或拖拽编辑器**。学校可维护常用筛选、默认首页校区和表格显示列，但不得改变核心统计口径。

## 14. 接口、数据存储和部署要求

### 14.1 接口清单

| 接口/数据源 | 用途 | 启动优先级 | 无对接时处理 |

| IoT实时值/时序历史 | 电水气热量计算及趋势 | P0 | 必须具备按时段查询，或确定有效数据拉取方案 |

| 课表/场馆开放安排 | 精确识别教学时段 | P1 | 按建筑开放时间估计，输出说明 |
| 气象数据 | 天气因素及节能项目效果比较 | P2 | 暂不出天气调整后的结论 |
| 运维/EAM工单系统 | 工单执行与设备资产联动 | P1 | 使用内置轻量工单 |
| 学校统一身份认证SSO | 账号和权限管理 | P1 | 使用本系统账户，不绕过角色和审计 |

### 14.2 建议的内部数据对象

`campus`、`building`、`building_usage_history`、`department`、`energy_meter`、`metering_point`、`iot_binding`、`metering_relation`、`reading_series`、`energy_interval_value`、`data_quality_event`、`energy_statistic`、`academic_calendar`、`opening_hours`、`price_plan`、`utility_bill`、`cost_allocation`、`alarm_rule`、`alarm_event`、`work_order`、`metric_definition`、`calculation_version`、`report_snapshot`、`audit_log`。

不将这些内容视为必须采用某数据库的物理表结构；它们是需求层面的逻辑实体，实施方需落实唯一编码、引用关系、有效期和变更历史。

### 14.3 数据访问与安全

- 网络区划遵循现有校园网络安全制度；IoT 内网与对外 Web 管理平台采取必要的访问控制和最小权限。接入凭据加密储存，通信链路采用适用安全措施。
- 根据定级及适用规范开展网络安全等级保护相关工作，不能未经定级一概宣称平台必须“等保二级”。
- 按角色和责任校区做服务端数据授权；宿舍房间信息、负责人联系方式、财务账单按最小必要范围展示。
- 对采集失败、运算失败、任务积压、数据库异常、接口不可达等提供独立技术监控。业务告警和平台故障告警区分处理。
- 数据保留期限、备份/恢复目标、离线归档、日志留存根据学校管理要求、合同和适用法律确定；建议在实施阶段明确恢复点目标RPO和恢复时间目标RTO并验收。

### 14.4 推荐实施技术边界

已有 IoT 平台提供设备及原始采集数据；校园能耗应用包含服务端统计与存储、前端 Web 管理页面、权限审计和必要定时计算。若后续仅开发前端演示版，需另行确定离线数据或接口仿真方案，但**演示版不等于满足本需求的数据质量、长期计量和安全上线条件**。

## 15. 非功能需求（建议验收值，不属于引用标准强制条款）

| 类别 | 建议要求 | 测试说明 |
|---|---|---|
| 页面性能 | 常用首页及列表首屏在约定数据规模下 P95≤3秒，复杂年度分析 P95≤8秒 | 约定服务器规格/并发用户数/缓存命中及查询数据量 |
| 实时数据时效 | IoT 当前值和管理页面的端到端更新延迟以 IoT 上送频率为依据，目标为数据到平台后≤60秒更新 | 不是把15分钟采样数据宣称为秒级实况 |
| 统计正确性 | 在覆盖完整、输入合法的验收样本中，内置公式与人工复核一致 | 区分浮点舍入、单位转换与显示精度 |
| 数据完整性 | 验收期关键计量点日数据有效覆盖率目标≥98%（前提是上游IoT能力满足） | 上游采集缺失不应记为能耗系统算法错误，但须正确提示 |
| 异常闭环 | 100% 告警事件可定位、派单、填写处理与复核结果 | 同一事件重复消息不生成无限重复工单 |
| 校历功能 | 可按学年/学期/假期/教学日分析相应建筑时段用能 | 日历版本变动后统计正确重算 |
| 权限控制 | 受限角色不可通过页面/API获取未授权校区或宿舍/账单明细 | 正向/反向越权测试 |
| 导出一致性 | 报表与同条件页面的总量、单位、过滤条件一致 | 审查缺数、估算、人工补录标记 |
| 审计追溯 | 关键修改可追到操作者、时间、变更字段、批准状态 | 验证计量点换绑及历史重算 |
| 稳定性 | 关键计算任务失败可重试且幂等，历史补传不重复计数 | 模拟断网、重复数据、重启 |
| 浏览器适配 | 学校使用的主流桌面浏览器近期版本正常使用 | 具体清单按学校办公环境确认 |

**非功能验收前置条件**：明确校区数、建筑数、计量点数、IoT 历史数据量、典型并发用户数、查询时间跨度和部署资源；否则单独给出“系统响应1秒”没有可验证意义。

## 17. 分期建设建议

### 17.1 第一阶段 P0：形成“校园能耗监测与管理闭环”

**建设模块**：基础建筑档案、计量器具与 IoT 绑定、数据治理、校园能源驾驶舱、电水气热监测（按实有条件）、楼宇详情、校园总量/分类分项/排行/趋势/教学日历分析、能效基础指标、费用概览与账单核对、告警工单、固定报表、角色权限及审计。

**阶段成果**：
- 学校可以查清每栋楼在何时使用多少能源；
- 管理人员可以说明数据从哪里来，缺了多少，统计边界是什么；
- 学期/寒暑假分析能准确区分不同时间；
- 常见异常可以派单处理，月度能源账单可以与系统数据核对；
- 无需配置化拖拽平台，即可使用全部首期核心功能。

### 17.2 第二阶段 P1：针对校园特色开展精细化管理

**建设模块**：实验室、宿舍、食堂、场馆专题；学院责任能耗和共享分摊；集中能源站、水资源平衡、能源预算、节能项目、年度节能考核、公共机构专项报表。

**前置条件**：需具有相应专用计量点及责任组织数据，食堂供餐/宿舍入住/实验专用设备等业务数据能够有效取得，否则部分能效指标只能处于“暂不支持计算”状态。

### 17.3 第三阶段 P2：按实际项目扩展

**可选内容**：光伏自发自用统计、天气与使用强度校正分析、设备能效预测、年度节能项目归因分析、学校能源碳排专题、科研场景专项报告、校区电子地图优化。

**边界**：碳排放核算/绿电权益证明、AI节能预测和优化控制另立专项需求，不在当前 V1.0 中预先承诺实施效果。

## 18. 项目实施前必须明确的问题

| 待确认事项 | 为什么影响需求/报价 | 建议默认处理 |
|---|---|---|
| 学校类型与规模 | 高校、中小学及多校区管理差异大 | 默认高校、多校区，但支持单校区 |
| IoT 现有接入覆盖 | 决定哪些 P0 页面有真实数据、是否需补表 | 先普查设备与历史数据能力 |
| 能源品种 | 是否存在天然气、热力、冷量、生活热水、光伏 | 根据已有能源开关展示对应固定页面 |
| 建筑分类/面积 | 单位面积和同类排名的分母及分组 | 学校提供权威建筑台账 |
| 总表/支表计量边界 | 是否具备可靠总量、覆盖率和水平衡 | 先做计量关系核查与人工映射 |
| 学年日历和开放时段 | 假期、考试周分析质量 | 由教务/后勤提供学校官方学年安排 |
| 学生人数/宿舍入住/供餐量 | 生均、入住人均和餐均指标能否上线 | 无有效数据时隐藏或显示暂不可计算 |
| 电力合同及价格规则 | 决定峰谷、需量、容量、基本费和最终对账 | 以真实有效账单和合同为准 |
| 组织与费用归属 | 一栋楼多学院共享如何核算 | 首期以楼宇核算为主，二期分摊 |
| 计量法制和监管要求 | 贸易结算/内部分析及公共机构上报要求不同 | 确认适用地域与业务身份，避免误用旧标准 |
| 当前学校业务软件 | 是否已有 EAM、财务、教务、宿管、资产系统 | 优先对接而非重复建设 |
| 安全与部署 | 校园私网、云部署、统一认证、网络安全定级 | 由校方信息部门提供边界和标准 |

## 19. 需求追溯与文档使用说明

- **业务功能与界面设计**：第5—10章供产品经理、UI/UX 和开发人员落实页面、字段与操作。
- **统计口径与数据正确性**：第3—4、11章供能源管理负责人、计量工程师及开发测试对账。
- **校园日历、费用和特殊场景**：第6—9、12章供教务、后勤、财务及学院业务负责人评审。
- **技术实现与验收**：第13—17章供项目经理、开发架构师、安全负责人、测试人员使用。
- **尚未确认的学校具体条件**：第18章必须在设计评审期间形成确认表；未取得相应 IoT 点位、业务分母或账单资料前，不应声称相关分析“已接入并真实可用”。

### 19.1 V1.0 设计结论

本系统的产品主线是：**能源数据接入—计量台账与边界核对—学校/校区/建筑能源监测—分类分项分析—校园教学生活场景诊断—费用与节能管理—异常处置与报表**。平台在保留必要的点位和基础业务维护能力的同时，取消复杂的通用配置产品思路，以学校后勤实际工作流程为中心，提供明确、稳定、可验收的校园能耗管理功能。
