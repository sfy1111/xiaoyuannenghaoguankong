# 明川大学校园能耗管理系统（前端 Demo）

面向高校后勤能源管理的多页面 Web 业务平台前端演示。**本项目是前端演示版**：所有学校、人物、能耗与账单数据均为演示预制的虚构数据（虚构高校“明川大学”），非真实采集数据；系统未连接任何真实 IoT 设备、后端服务或身份认证，不冒充生产系统。

## 技术栈

- React 18 + TypeScript（strict）+ Vite
- Ant Design 5（UI）+ Apache ECharts 5（图表）
- React Router（真实 SPA 路由）、dayjs、Zustand（轻量共享状态）
- 数据全部由 `src/data/**/*.json` 驱动；确定性时序引擎按参数化种子生成小时级数据（小时和＝日量、日量和＝月量）
- 测试：Vitest（业务计算与数据一致性 38 项用例）

## 运行

```bash
npm install
npm run dev        # 方式一：开发模式，浏览器打开 http://localhost:5173
npm run typecheck  # tsc --noEmit
npm run test       # vitest 业务计算测试 + jsdom 界面冒烟测试
npm run build      # 生成单文件 dist/index.html（全部 JS/CSS 内联）
npm run preview    # 方式二：本地服务器预览构建产物 http://localhost:4173
```

**正确打开方式（重要）**

| 方式 | 操作 |
|---|---|
| 开发调试 | `npm run dev` 后访问 http://localhost:5173 |
| 构建后预览 | `npm run build` → `npm run preview` 后访问 http://localhost:4173 |
| 双击打开 | `npm run build` 后直接双击 `dist/index.html`（单文件产物 + Hash 路由，无需服务器） |
| 其他静态服务器 | 把 `dist/index.html` 放到任意静态服务器/目录服务下即可 |

常见空白页原因：直接双击**项目根目录**的 `index.html`（它是开发入口，引用 TSX 源码，浏览器无法直接执行）；或经 file:// 协议打开**未内联的旧构建**（ES Module 被浏览器 CORS 拦截）。请使用上表方式。构建产物已内联全部资源并使用 Hash 路由，双击 `dist/index.html` 亦可正常运行。

## 数据时间范围与口径

- 数据窗口：**2025-09-01 至 2026-10-21**（asOf = 2026-10-21 08:00），各页面“本日/本月/同比”默认基于同一演示日期。
- 电力按校区进线关口表（购入边界）、水按总进水表统计；建筑按主表，分表仅作分项，父子表不重复相加。
- 缺失/无效样本不按 0 计入并保留标记；估算与人工修正计入并标注质量。换表按事件规则处理，不产生负用量。
- 电费测算仅含分时电度费（不含基本电费/需量费/税费）；未配置能源折标系数，不展示综合吨标煤。
- 校历：2025-2026 学年（秋/春学期、期中期末考试周、寒暑假、法定假日）与 2026-2027 秋季学期。

## 核心演示路径

1. **校园总览 → 楼宇 → 计量点**：`/dashboard/campus` 切换校区/日期 → 点击建筑排行 → 楼宇详情 → 计量点读数与 15 分钟采样；返回后筛选保留（URL 参数）。
2. **教学日历 → 时段分析**：`/base/calendar` 修改特殊日/开放时间 → `/analysis/calendar`、`/scenarios/teaching` 查询随新校历重算。
3. **夜间用水 → 告警 → 工单闭环**：`/monitor/water` 夜间最小流量 → `/alarms/AL-2026-0412` 确认/派单 → `/work-orders` 接单/反馈/复核关闭；驾驶舱待办与审计同步，刷新后状态保留。
4. **分时电价 → 费用 → 账单**：`/costs/pricing` 调整/新增价格方案（重叠校验）→ 费用测算变化 → `/costs/bills` 差额刷新而账单金额不变，填写原因后核对归档。
5. **新建筑台账与计量绑定**：`/base/buildings` 新增建筑（默认无数据）→ `/base/metering` 逐点选择候选 IoT 属性（语义校验拦截瞬时量绑定累计点）→ 绑定后纳入统计。
6. **月报 → 预览 → 导出**：`/reports` 生成月报/日报/学期报/年报 → 导出真实 CSV/XLSX（含统计口径与数据质量说明）。

## 可维护业务数据（增删改查能力）

所有修改经统一数据服务写入状态、localStorage 持久化并写入审计（时间线可在「系统管理→审计」追溯）：

| 模块 | 可维护操作 |
|---|---|
| 建筑档案 | 新增（编码唯一校验）/编辑/停用/重新启用 |
| 组织单位 | 新增（编码唯一）/编辑，责任归属与分摊比例维护（合计100%校验） |
| 校历 | 特殊日新增/删除、开放时间编辑、学期/假期新增/删除（同类型重叠校验）、考试周新增/删除（须落学期内且不重叠） |
| 计量器具 | 新增（表号唯一）/换表（旧表终止示值归档）/停用（理由必填） |
| 计量关系 | IoT属性逐点绑定/解绑（语义校验）、计量拓扑新增（防重复/防环/能源一致）/移除 |
| 数据质量 | 补录申请提交/审批通过/退回（原缺失样本保留） |
| 价格方案 | 新增/编辑（同对象有效期重叠校验）/停用，试算 |
| 账单 | 录入供应商账单（编号唯一、金额固定）→ 差异原因 → 核对 → 归档 |
| 预算 | 按月/能源调整（原因必填，原版本保留） |
| 告警/工单 | 确认/派单/接单/反馈/复核/关闭/误报/暂挂/重开，规则阈值与启用维护 |
| 节能项目 | 新建/编辑/验收归档（评估结论必填）；节能目标调整 |
| 用户 | 新增（账号唯一）/角色调整（权限授予与回收）/停用/启用 |

不提供物理删除的实体（建筑、账单、告警、器具历史）按业务规则以停用/归档替代，历史数据与审计全部保留。

## 业务说明与边界

- 遗留告警三个阶段示例：待确认（致知楼国庆假期用电）、处理中（兰园1号夜间用水，关联工单）、已关闭（兰园2号采集离线，含已审批补录与待审核补录）。
- 2026-09 东校区电费账单含“基本电费及功率因数调整费”，供对账差异演示。
- 学院责任/费用分摊页区分“实测”与“分摊”，共享池比例合计强制 100%。
- 宿舍页仅展示楼栋聚合与人均指标，不包含任何学生个人或房间明细；不提供远程断电等控制功能。
- 能源站输入电/气与产出冷/热/热水三本账分开，杜绝内部转换重复统计。
- “重置演示数据”入口仅在 `系统管理 → 数据接口与采集状态` 页，有二次确认。

## 已知限制（演示版）

- 前端权限（角色/校区范围）为演示用途，生产环境必须由服务端做数据授权。
- 电压/电流/功率因数、供回水温度与流量未接入源数据，相应图表不展示（如实提示未接入）。
- 10 月供应商账单未出账（月结后导入），账单页不虚构该月账单。
- 报表 PDF 未实现（按需求优先做通 CSV/XLSX 导出）。
- 数据由确定性生成引擎按 JSON 参数推演，不代表真实表计抄见值。
